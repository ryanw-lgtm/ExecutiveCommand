# Local AI runtime

> **Current production setup (Iteration 5):** Qwen3-4B-Instruct-2507 Q4_K_M (Apache-2.0), downloaded in-game on first launch and SHA-256 verified; Windows `llama-server.exe` cross-compiled from source and bundled. See DEVLOG for measured performance. Next: a Vulkan (GPU) build for faster replies on gaming PCs.

## How it works

* `LlamaServerModel` launches the bundled `llama-server` on `127.0.0.1` on a free port, polls `/health`
  (Starting → Loading → Ready), and calls `/v1/chat/completions`.
* **Interpretation** uses `response_format: json_schema` (grammar-constrained) with a schema generated
  from the action registry, bounded string lengths, temperature 0.1, and a 60 s timeout. It is only used when
  the rule-based interpreter cannot tell what the player meant.
* **Dialogue** uses temperature 0.7, at most 110 tokens (1–3 sentences), a 120 s timeout and one retry with
  feedback if validation rejects the draft. Cancellation closes the HTTP
  request, and the server aborts generation (tested: under 300 ms, server still healthy afterwards).
* Every failure path (missing files, crash, timeout, truncation, invalid or implausible output) returns
  `null`, and the game falls back to deterministic behavior.
* No network access other than loopback, no account, and no telemetry.

## Verified in this environment

Built llama.cpp `llama-server` from source (commit `29b52d3`, MIT) for Linux/CPU. Integration tests
(`LlamaIntegrationTests`) run the real binary against `models/test-tiny-random.gguf`, a **random-weight**
model generated by `tools/make_test_model.py` from llama.cpp's Qwen2 vocabulary file. This verifies the
following:

* startup and health transitions, and clean shutdown;
* grammar-constrained JSON is schema-valid (5/5) and parses into interpreter output;
* gibberish dialogue is rejected and the scripted fallback is used;
* timeouts and cancellation;
* graceful degradation with a missing model.

**Not verified:** dialogue quality, interpretation accuracy, latency and memory with a *real* 7–8B model.
Hugging Face was unreachable from the build environment. This is the next AI task.

## Preparing a dev machine

```bash
git clone https://github.com/ggml-org/llama.cpp && cd llama.cpp
```

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release -DLLAMA_CURL=OFF && cmake --build build --target llama-server -j
```

Copy `build/bin/llama-server` and its shared libraries into `runtime/llama/`, then put a GGUF model in
`models/`. On Windows, use the official llama.cpp release zips (CPU, Vulkan or CUDA builds) and copy
`llama-server.exe` and its DLLs into `runtime/llama/` next to the game executable.

Benchmark plan (scripted through `MeetingService` and a fixed corpus of player lines with expected
actions): structured action accuracy, clarification rate, role consistency, manipulation resistance
(injection corpus), validator rejection rate, p50/p95 latency, peak RAM/VRAM, on CPU-only 16 GB and on a
mid-range GPU.
